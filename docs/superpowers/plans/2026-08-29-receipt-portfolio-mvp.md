# Receipt Portfolio MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and validate a local, static MVP of Search Receipt, Workflow Test Lab, and SkillLedger from an append-only evidence engine and fixture-backed automated pipeline.

**Architecture:** One strict TypeScript workspace contains a pure evidence package, a manifest and fixture corpus, and a deterministic static-site renderer. Collection candidates are validated, canonicalized, hashed, diffed, policy-gated, and written as append-only receipts before a site can render them. The first release uses fixture sources plus a live-source dry-run command; scheduled automation is present but cannot publish without a verified evidence build.

**Tech Stack:** Node.js 24, npm workspaces, TypeScript, Vitest, Zod, ESLint, Prettier, static HTML/CSS generated by TypeScript, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-29-receipt-portfolio-design.md`

## Global Constraints

- Fetch only manifest-allowlisted public HTTPS sources; fixture tests make no network call.
- Raw bytes are hashed before parsing. Receipts are named by a canonical payload SHA-256 and never overwritten.
- All fetched content is untrusted data: never execute, dynamically import, or render it as HTML.
- An automated public record must state source facts only and include source URL, observed time, raw hash, normalized hash, manifest hash, and policy result.
- Use `PASS`, `REVIEW_REQUIRED`, or `REJECTED`; never claim proof, truth, completeness, safety, ranking effect, or profit.
- No user accounts, payments, third-party scripts, analytics, credentials, arbitrary URLs, external prompt execution, or skill execution in this release.
- Every executable behavior follows a red-green test cycle and every task receives independent review before merge.

  siteId: z.enum(['search-receipt', 'workflow-test-lab', 'skill-ledger']),

- [ ] **Step 3: Implement canonical serialization, raw-first hashing, and explicit gate decisions**

```ts
export type GateDecision = 'PASS' | 'REVIEW_REQUIRED' | 'REJECTED';

export function evaluatePublication(candidate: Candidate): GateResult {
  if (!candidate.manifestValid || !candidate.rawSha256 || !candidate.normalizedSha256) {
    return { decision: 'REJECTED', reasonCodes: ['INCOMPLETE_EVIDENCE'] };
  }
  if (candidate.ambiguous || candidate.diffRatio > 0.6) {
    return { decision: 'REVIEW_REQUIRED', reasonCodes: ['AMBIGUOUS_OR_LARGE_CHANGE'] };
  }
  return { decision: 'PASS', reasonCodes: ['SOURCE_FACTS_ONLY'] };
}
```
